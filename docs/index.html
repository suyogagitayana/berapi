01 / GET STARTED

Installation

You’ll need Git and Node.js 20 or newer. Clone the berAPI repository, open the project folder, and start the server: 

git clone https://github.com/suyogagitayana/berapi.git
cd berapi
npm start

Open http://localhost:3000. Four example endpoints are ready to explore. There are no packages to install.

The server binds to your machine’s loopback address. Keep the terminal running while you use your APIs. Press Ctrl+C to stop it.
Use a different port

PowerShell:

$env:PORT=4000
npm start

macOS / Linux:

PORT=4000 npm start

Your workspace and endpoint URLs will use the new port.

02 / MAKE SOMETHING RESPOND

Create an endpoint

  1. Click New endpoint and give it a name in Settings, such as “All users”.
  2. Choose an HTTP method and path, for example GET /api/users.
  3. Open Response body and write the JSON your frontend expects.
  4. Click Save endpoint, then Test request to see the actual response.
  5. Click Copy URL and use it in your frontend.

You can edit an example instead. Each method and path combination must be unique. Query strings don’t change which endpoint matches.

03 / THE EVERYDAY STUFF

Simple API

Simple API gives you the essentials: HTTP method, URL path, and response body. JSON is validated when you save. Use Format JSON to tidy it up.

Settings let you rename or disable an endpoint. A disabled endpoint returns 404 until you turn it back on. New endpoints default to status 200, JSON, and no added delay.

Switching modes preserves your settings. If you previously chose a different status or format in Advanced API, those settings still apply in Simple API.
04 / A LITTLE MORE CONTROL

Advanced API

Switch to Advanced API to control these response settings:

Setting What it does
Status code Choose 200–599. Try 201 for creation, 401 for signed-out screens, or 500 for error states. HTTP 204, 205, and 304 have no body.
Response format JSON, plain text, or HTML. This sets the default Content-Type. JSON requires valid JSON; text and HTML accept raw content.
Response delay Add 0–30,000 ms of latency to exercise loading states.
Headers Set custom response headers using a JSON object with string values. 
{
  "X-Total-Count": "42",
  "Cache-Control": "no-store",
  "Access-Control-Expose-Headers": "X-Total-Count"
}

berAPI manages CORS origin and transport headers. Use Access-Control-Expose-Headers if your frontend needs to read custom response headers.

Network throttling and error simulation

Open Advanced API → Settings → Network & errors. Apply a preset, or adjust each setting:

  • Slow connection: adds 2 seconds of delay plus a random 0–1 second. Custom delay and random extra delay each support up to 30,000 ms.
  • Unreliable: returns a simulated error on approximately 30% of requests. Set Error frequency to 0% for normal responses or 100% to always fail.
  • Error presets: quickly return 401, 404, 500, or 503. Choose any error code from 400–599 and edit the separate JSON error body. Your regular response body stays intact.
  • Request rate limit: allows a fixed number of requests per window, shared by all clients and parameter values for this endpoint. The preset allows 5 requests per 60 seconds. Extra requests return 429 immediately with a Retry-After header readable by your frontend.

The rate limit is disabled when Allowed requests is 0. Windows start on the first request and reset when the interval expires. OPTIONS preflight requests do not count. Accepted requests count even when they return a simulated error. Limits reset on server restart, or when the endpoint’s route, enabled state, or rate-limit settings change.

Click Save endpoint before testing. Simulation settings persist across restarts and still apply in Simple API. Choose Normal response and save to clear delays, error simulation, and rate limits. This preset preserves your regular status, format, headers, and body.

Dynamic paths

A path such as /api/users/:id matches a single segment like /api/users/123. Replace parameters in the copied URL before using it. Every match returns the same saved response; path values and request bodies are not interpolated. If paths overlap, the first matching endpoint in workspace order wins.

05 / CONNECT THE DOTS

Connect your frontend

Point your frontend at the URL you copied:

const response = await fetch(
  'http://localhost:3000/api/users'
);

if (!response.ok) {
  throw new Error('Could not load users');
}

const data = await response.json();
console.log(data.users);

GET, POST, PUT, PATCH, and DELETE are supported. berAPI handles OPTIONS preflight automatically and allows requests from other origins. For POST, choose a POST endpoint and add method: 'POST' to fetch.

Responses are static mocks. POST, PATCH, PUT, and DELETE return what you saved; they don’t mutate other endpoints. Cookie-based credentialed CORS is not supported.

Open Request activity to see the last 100 mock requests, their status, and server response duration. Logs refresh every four seconds and reset when the server restarts.

06 / KEEP IT ORGANIZED

Workspace storage and backups

Endpoints are saved in data/endpoints.json and survive restarts. This folder is ignored by Git. Click Export to download your saved workspace as JSON, or Import to replace the workspace with a previous export. Export a backup before importing.

berAPI supports up to 500 endpoints and a 2 MB workspace upload. Import validates the entire file before saving. Use the search box to find an endpoint by name, method, or path.

Troubleshooting

The port is already in use

Stop the other process or choose a different PORT using the commands under Installation.

My endpoint returns 404

Check the method and path, save your changes, and make sure the endpoint is enabled. Paths are case sensitive. Replace dynamic parameters with real values.

My frontend cannot connect

Keep berAPI running and use its printed URL, including the port. Your browser must be on the same machine. Use HTTP for local development; an HTTPS page may block HTTP requests.

My JSON will not save

Check for trailing commas, missing quotes, and comments. The response must be valid JSON. Switch to text in Advanced Settings for a non-JSON response.

The server fails to load saved data

Back up data/endpoints.json and check that it contains a valid berAPI export. To start fresh, stop the server and rename that file. Restart to recreate the example workspace.
